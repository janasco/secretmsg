Notes

What this is and is not

  • Not running code. These are static frames in a browser. No Flutter, no Dart, nothing wired to the API — they exist so the visual direction can be argued before anyone rewrites a real widget.
  • Tokens are shared on purpose. The same palette, type scale and radii serve both renderers. If the redesign lands, it lands as one token change in lib/theme.dart plus index.css, then screens follow.
  • The a11y gate is the real constraint, not taste. tool/a11y/lint.dart scans both clients for theme-blind literals and computes a full contrast matrix. Any implementation is gated by it, so the prototype does not propose colours that would fail it.
  • 44px minimum touch targets and a 68px tab bar, matching what the existing design constitution already specifies. Nothing here depends on hover — that is a desktop affordance the phone build has never had.
  • Fonts are approximate. Inter is loaded from Google Fonts for the preview; the real app already bundles or falls back to it, so nothing here depends on the network.
